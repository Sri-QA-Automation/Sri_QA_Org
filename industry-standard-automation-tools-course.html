Part 12 Performance Testing with JMeterJMeter · Load, stress, spike and soak tests

You load test LLM-powered APIs with Apache JMeter and learn to read the results.

JMeter foundations

TopicWhat you learn
What JMeter isAn open-source Apache tool that simulates many virtual users and reports response times, throughput and errors
Why test LLM apps for performanceModel calls are slow and costly, vector search and APIs add delay, and providers apply rate limits
Main componentsTest Plan, Thread Group (users, ramp-up, loops), samplers such as HTTP Request, config elements such as Header Manager and CSV Data Set Config, timers, assertions, listeners
Ramp-up and think timeGradual load increase, and pauses between actions that imitate real user behaviour

Load testing an LLM API

  • An HTTP Request that POSTs a JSON body to the endpoint
  • A Header Manager with content type and authorization
  • A CSV Data Set Config that feeds different prompts
  • Assertions on HTTP status and expected JSON fields or keywords, so fast error pages are not counted as successes
  • A Thread Group with the users and ramp-up

Test types and metrics

TopicWhat you learn
Load testExpected user numbers
Stress testBeyond capacity, to find the breaking point
Spike testA sudden jump in users
Soak testSteady load over a long time, to find leaks and degradation
Metrics that matterResponse time (average, p90, p95, p99), time to first token for streaming apps, throughput, error rate, token usage and cost
Why percentilesAverages hide slow outliers; p95 or p99 shows what the slowest users experience

Running tests and finding bottlenecks

  • Run JMeter in non-GUI mode from the command line, because the GUI uses resources and can distort results
  • Generate an HTML report from the results
  • Look for bottlenecks in model inference, the vector database, embedding calls, network, rate limits, application code or too few workers
  • Handle the challenges: streaming responses, variable response length, rate limits and cost, non-deterministic content
  • Use a local or mocked model for heavy load and keep real-API tests small
jmeter -n -t llm_test.jmx -l results.jtl -e -o report

Python, Playwright, PyTest, Ollama, OpenAI API, LangChain, DeepEval, an MCP server, JMeter and GitHub Actions, all used together in one final project.
